01 · BEFORE

Upstream: a smart-home demo whose tools only print

Espressif's openai_demo as it ships, built for the ESP32-S3-Korvo-2. The plumbing is excellent: WebRTC to OpenAI, Opus both ways, a data channel for events and tool calls. But every tool handler is a printf, the session opens at boot and stays open, and the stock app does not fit the stock partition.

02 · AFTER

This fork: a bench lab assistant on the ESP32-S3-BOX-3

Same WebRTC spine, new ends. The tools drive a pair of DAC7578s on the dock's I2C bus behind firmware clamps, a wake word keeps the box off the network until it is spoken to, the mic closes while the box talks, and the screen shows what happened. Copper marks everything this fork added or changed.

03 · ONE REQUEST, END TO END

How a sentence becomes a voltage

The model decides what to do; the firmware decides what's allowed. The model sometimes sends the channel as the string "3", the clamp runs before any I2C traffic, and only the real outcome goes back to the model.

Out of bounds: “Set channel three to five volts”
The clamp refuses before any I2C traffic. The model gets the reason, the screen shows it in red, and the reply says it can't. Nothing is clipped to a nearby value and nothing is written.
{"ok":false,
 "error":"refused by firmware clamp: channel must be 0-15 and millivolts 0-3200"}
04 · SESSION LIFECYCLE

Offline until spoken to, closed when idle

A realtime session costs money for as long as it is open. Upstream opens one the moment Wi-Fi comes up and keeps it until someone types stop. This fork listens locally for the wake word, opens a session only when spoken to, and closes it after two quiet minutes.
